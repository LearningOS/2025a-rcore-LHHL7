# 一 实现功能
重写 sys_get_time 和 sys_trace
实现mmap 和 munmap 匿名映射
mmap:
申请长度为 len 字节的物理内存（不要求实际物理内存位置，可以随便找一块），将其映射到 start 开始的虚存，内存页属性为 prot
munmap:
取消到 start, start + len 虚存的映射
# 二 问答题
## 1.
PPN：物理页号（Physical Page Number）
V(0) ：Valid，置 1 表示条目有效
R(1) ：Readable
W(2) ：Writable
X(3) ：Executable
U(4) ：User，仅用户态可访问
G(5) ：Global，TLB 全局项
A(6) ：Accessed，CPU 已访问过
D(7) ：Dirty，CPU 已写过

## 2.
### 1.
 Instruction page fault（取指缺页）
 Load page fault（读数据缺页）
 Store/AMO page fault（写数据缺页
### 2.
scause ：异常码（12/13/15）
 stval ：触发异常的虚拟地址
 sepc ：异常指令的 PC，供返回重试
 satp ：当前页表根物理页号（用于定位页表）
### 3.
Lazy 策略的好处
1. 
加快进程启动：代码/数据按需载入，无需一次性 I/O。
2. 
节省内存：未用页面不占用物理帧。
3. 
提高多程序并发：物理内存留给真正活跃页面。
4. 
支持稀疏地址空间：大数组、大堆栈可先预留 VA 而不耗 PA
### 4.
SV39 三级页表，每页 4 KiB，可映射 512 项。
叶子页表（L0）数量 ≈ 10 GB / 2 MB ≈ 5 × 10³ 张
每张叶子页表本身 4 KiB → ≈ 20 MB
### 5.

 mmap  仅记录“VA 区间 + 磁盘文件偏移”到 VMA 列表，不实际分配物理页、不填页表。
首次访问 → CPU 抛缺页异常
进程退出时遍历 VMA，对未实际驻留的页跳过写回，减少 I/O
### 6.
被换出的页面其 PTE：
Valid 位清 0
PPN 字段改写为 swap 分区中的槽号/扇区编号（或特殊编码）
再次访问即触发缺页，内核根据槽号把页读回内存，恢复 Valid 并更新 PPN。
## 3.
### 1.
只需写  satp  并执行  sfence.vma  刷新 TLB，即完成切换
### 2.
阻止用户态访问内核页
 把内核对应 PTE 的 U 位清 0；用户态访问会触发 page fault，CPU 自动进入内核模式处理。
### 3.
单页表优势
无需频繁切换  satp ，上下文切换开销小；
TLB 刷新次数少，缓存利用率高；
### 4.
双页表 OS：
每次进出内核（系统调用/中断/异常）都要切换：用户页表至内核页表。
单页表 OS：
仅在创建新进程/销毁旧进程时整体替换  satp

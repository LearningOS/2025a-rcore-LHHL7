# 一 实现功能

## 2.
实现系统调用sys_enable_deadlock_detect
功能：为当前进程启用或禁用死锁检测功能。
说明：
开启死锁检测功能后， mutex_lock 和 semaphore_down 如果检测到死锁， 应拒绝相应操作并返回 -0xDEAD (十六进制值)。
## 3.

在pcb中新维护了deadlock_detect变量
# 二 问答题
## 1.
主线程退出时要回收的资源
1. 
各子线程的 TaskControlBlock（内核堆分配）
2. 
各子线程的用户/内核栈 KernelStack（整块内存对象）
3. 
各子线程的 trap 上下文页（trap_cx_vec）
4. 
进程级资源：
内存映射集  memory_set （含页表、各段）
打开文件表  fd_table 
mutex / semaphore 列表及其等待队列（可能被子线程引用）
5. 
主线程自己的 TCB、栈、trap 页（最后由  exit  系统调用统一释放）
## 2.
区别点                   Mutex1                     Mutex2 
自旋还是阻塞           自旋（loop 重试）        只判断一次，失败就阻塞 
unlock 时是否立即清locked  是（19 行）        否（44 行才清，且仅当无等待者） 
唤醒策略          无条件清标志，再唤醒一个等待者   只有存在等待者时才清标志，否则保持  locked = true  

可能导致的问题
对于mutex2
 若 unlock 时队列为空， locked  仍为  true ；后续再来 lock 会直接认为“已上锁”并阻塞自己，结果——锁永远没人能再拿到，整个系统死锁。
